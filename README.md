# TestHub 1.3.3

TestHub 是面向可信内部测试团队的 UI 自动化平台：需求/PRD → 测试计划 → 页面采集 → 模块与用例脚本 → Playwright 执行 → 在线报告与修复。前端为原生 JavaScript，API/Worker 为 Node.js ESM，脚本使用 TypeScript，数据存储于 MySQL 8.4，浏览器使用 Chromium。


## 1.3.3 本次更新

- 发给模型的页面依据使用字段白名单：保留控件、定位路径、表格列结构；剔除查询结果、样本行、容器拼接文本及旧版自动填充的测试数据。原始采集记录仍保留在平台供查看，不直接发给模型。手填测试数据可选；旧自动数据不会自动迁入手填字段。此优化不截断定位依据，也不承诺完整计划与所有控件合计必然小于 20000 字符。
- 缺失用例补齐窗口新增“补充生成指令”，每次最多 10000 字符，随所选用例生成、校验修正和自动定向探索传递；已有脚本保持不变。指令不能替代真实定位证据或降低业务断言。
- 覆盖完整、缺口解决、静态检查通过后即可人工审核并执行，无需先试运行。模块/单条试运行及生成时浏览器验证保留为可选诊断工具，历史试运行失败不再阻塞审核。

## 1. 1.3.3 的变化

本次以 1.3.1 为基线，保留注册、项目所有者和数据权限等已有功能。源码增量包用于覆盖现有项目，不含原部署文件、`.env`、数据卷和依赖目录；无新增依赖、数据库表或迁移。

1. Ant Select 同时记录隐藏辅助 option 和实际可见弹层中的选项；补充选中值回显、弹层所属字段、前置状态。定向探索可在已观察到的搜索输入中搜索缺口明确提到的目标选项，并在最多 3 次、总动作预算内滚动虚拟列表；不选择业务值或提交查询。
2. 采集表格容器、数据行集合、表头及列映射；复杂合并表头无法可靠映射时不猜列号。每张表仍只保留前三行文本样本，同时独立记录可见行数。样本不能代表总数。
3. 采集分页原始摘要、可识别格式的总数、当前页、下一页/上一页及禁用状态、每页条数载体；解析不了的总数明确为未知。不自动翻页或修改 pageSize。
4. 候选分开记录 count 与 visibleCount；集合允许多匹配，点击仍要求唯一、可见且启用。空结果不能替代正向有数据用例；生成器收到完整表格结构，自动探索合并后也保留。
5. `liveValidation=false` 和探索建议不会成为额外业务禁令；缺少数据或规则仍报告缺口，不能删除业务断言来补齐脚本。
6. 测试计划“标注 / 重命名”“删除”“单用例管理”放入“查看 / 编辑”。单用例管理识别独立 Markdown 标题（如 `### TC-01 查询`），只编辑该段，保存后需重审；不支持自动拆分的表格计划继续全文编辑。保存带版本检查，拒绝覆盖已改变的计划。已有脚本模块保留原计划快照。

### 升级后如何处理 TC-02 / TC-04 / TC-07

保留原业务规则和 selectedData，在模块“查看 / 编辑 → 单用例管理”或“生成模块脚本”中选择缺失用例，开启自动 Explorer 补齐。老证据可继续使用，但没有真实选项/表格结构时必须让 Explorer 补充或在“页面采集与依据”更新；无需人工逐个填写选择器。登录态过期只更新登录态。

- TC-02：检查真实可见选项、回显、状态列和总数载体；“筛选后总数不变”若无业务依据，先修订计划。
- TC-04：由目标选项搜索/滚动补充依据；仍需真实存在匹配数据，前三行没有该处室不能证明数据不存在。
- TC-07：按真实摘要与 pageSize 确认第二页前提。真实数据不足时保留数据缺口，不能假装完成翻页。需求允许 URL 或页面状态时，可按已验证页面状态断言；明确要求 URL 时不能替代。

### 1.3.1 的变化（保留）

1. 登录页可自行注册账号。注册后默认测试人员，不自动取得其他项目或管理员权限。
2. 所有启用账号均可创建项目，创建人拥有该项目全流程权限。仍可访问管理员额外分配的项目。历史项目不根据名称或已有访问权自动推断所有者。
3. 平台密码最低 6 位，最高 256 位；适用于注册、创建/重置密码、修改密码和首次管理员初始化。已有密码保持有效。
4. 项目入口调整为“登录态”和“页面采集与依据”。取消 JSON 上传入口及其 API，统一通过平台浏览器保存登录态。已有保存的登录态文件继续使用。
5. 测试脚本按“项目 → 功能模块/版本 → 用例”展开，计划用例即使未生成脚本也可见。可单条生成或生成模块内全部缺失脚本。
6. 模块“标注/重命名”“删除模块”“单用例管理”集中在“查看/编辑”中。
7. 执行中心按“项目 → 功能模块 → 任务”组织；任务详情继续按用例折叠，步骤、错误、日志、分析和产物各自展开。
8. 版本号、统一文档与包元数据同步至 1.3.1。

## 2. 架构与持久化

| 组件 | 职责 | 技术/保存位置 |
| --- | --- | --- |
| Web UI | 项目、账号、计划、模块、执行与报告管理 | HTML/CSS/原生 JavaScript |
| API | 登录/注册、项目权限、业务 API、远程登录浏览器、报告服务 | Node.js 24+，默认端口 8080 |
| Worker | 领取任务、模型调用、Explorer、生成、验证、正式执行 | 单 Worker，Playwright 1.63.0 |
| MySQL | 记录、队列、账号、Worker 心跳 | MySQL 8.4 + mysql2，testhub-mysql 卷 |
| 文件数据 | 项目登录态、截图、日志、HTML/JSON/Trace/视频 | testhub-data 卷，容器 /app/data |

数据库包含 `records`、`jobs`、`workers`、`users`。records 的 JSON 保存项目、计划、脚本模块与页面依据；模块沿用 suite 记录，完整用例清单放在 manifest，已生成脚本仍可导出为一份 Playwright 文件。创建模块不会先生成占位测试。项目 ownerId 是服务器记录的创建人，不接受客户端指定或修改。

API 和 Worker 共用镜像，数据库异步连接池；队列事务领取，数据库锁保证单 Worker；登录态、报告不放在镜像层。项目权限覆盖接口、任务详情、下载、预览与在线报告资源。

这是一个单工作空间的可信内部平台，不是面向不可信公众的多租户代码执行服务。项目所有者能审核并执行自己的脚本，脚本拥有 Worker 进程能力；静态检查和项目接口权限不构成操作系统/容器级沙箱。注册入口应在团队内网访问范围内使用，不应作为公网匿名脚本执行服务开放。

## 3. 账号、密码与项目权限

登录页选择“没有账号？注册”，填写账号、姓名、密码和确认密码。账号为 3–64 位字母、数字、点、下划线或连字符；密码至少 6 位。注册不会自动登录，成功后使用新账号登录。

首次创建空 users 表时，平台创建 `admin`，初始密码取 `.env` 的 `ADMIN_PASSWORD`。后续密码以数据库中的 scrypt 加盐哈希为准，修改环境变量不会重置已有密码。用户可在左下角修改自己的密码；管理员可在人员管理中添加账号、重置密码、启用/停用和分配项目。

| 能力 | 管理员 | 自建项目的所有者 | 分配项目的测试人员 | 分配项目的只读人员 |
| --- | --- | --- | --- | --- |
| 查看数据、报告、下载 | 全部项目 | 自己的项目 | 获授权项目 | 获授权项目 |
| 新建自己的项目 | 是 | 是 | 是 | 是 |
| 修改项目环境、配置登录态 | 是 | 是 | 否 | 否 |
| 采集页面、管理计划/依据/脚本 | 是 | 是 | 是 | 否 |
| 审核脚本、未审核脚本试运行、生成时浏览器验证 | 是 | 是 | 否 | 否 |
| 执行已审核脚本 | 是 | 是 | 是 | 否 |
| 人员管理、给他人分配项目 | 是 | 否 | 否 | 否 |

所有者权限以项目为范围，不提升为平台管理员。只读角色对管理员分配的项目保持只读，对自己创建的项目拥有全流程权限。管理员可见全部项目，包括新注册用户创建的项目。

权限修改、停用、密码重置后旧登录会话和临时报告链接失效；修改自己的密码后需重新登录。Worker 在后续检查时停止提交者已停用或失去执行权限的任务，但不能撤销此前已发生的业务操作。管理员取消项目分配不会取消该用户的创建人身份；停用账号会使其不能使用任何项目。不支持所有权转让，历史无 ownerId 项目仍沿用原授权，由管理员管理环境及审核执行。

## 4. 项目、登录态与页面依据

### 4.1 创建项目

项目与环境 → 新建项目：填写名称、环境域名、入口路径和说明。例如环境 `http://172.23.5.62`、入口 `/organization/personManager`。不同项目独立保存地址和登录态，无需将业务地址写死进 Compose。

修改环境域名会清除该项目“已配置登录态”标记；修改环境或入口会使不匹配的页面依据不可再用于该项目。其他已保存项目和报告不受影响。

### 4.2 登录态

项目 → 登录态 → 打开登录页面。在平台显示的远程浏览器中人工输入账号、密码、验证码；支持点击、拖动、滚动、键盘、粘贴、弹出页面切换。中文可先点击目标输入框，再使用画面下方文本输入并发送。

人工确认已进入业务页面后勾选确认并保存。Cookie、localStorage、IndexedDB 存到该项目，不保存 sessionStorage。取消不会覆盖原登录态。最多两个并发登录窗口，同一项目一个，15 分钟到期；退出平台关闭所属浏览器。

登录浏览器位于 API 容器，采集和执行位于 Worker，因此两者都必须能访问业务环境。验证码由人工操作，平台不自动绕过极验，不保证所有远程/无头浏览器验证码兼容。保存状态不等同于自动证明业务认证成功；设备/IP 绑定、sessionStorage 依赖仍需针对目标系统适配。

不再提供上传 JSON。旧版已经保存的 JSON 文件不删除，继续在后台使用。登录画面和输入不送模型；画面仅在内存传输，不保存为报告。部署使用 localhost/SSH 转发或 HTTPS。

### 4.3 页面采集与依据

同一入口管理历史采集、启动新采集、查看截图、定位依据与表格样本、确认/修改数据。

- Explorer 先记录初始状态，再自动展开唯一且可见的已验证筛选控件，保留展开路径、状态和候选表达式。隐藏的其他字段不会阻塞当前无关用例；默认折叠不自动成为额外测试点。
- 除默认展开外，定向探索可从已验证选项中切换标签页或打开自定义下拉；支持在已关联的 Select 搜索输入中搜索目标选项、滚动已验证的虚拟选项列表；不执行保存、删除、提交或查询业务操作，不执行模型返回的任意代码/选择器。
- 支持嵌套 iframe 路径、角色/标签/placeholder/testId/id/name、Ant Design/Element 表单范围和空状态组件。重复候选只有实际筛选后唯一可见才可交互，不用 first()/nth() 猜测。
- 最多 8 个 frame，每 frame 240 个控件、5 张表，每表当前可见前 3 行。不是全站遍历、全量业务数据或数据库采集。
- 业务规则可留空，此时以已审核计划为准。测试数据/数据前提为可选手填，不自动填入页面查询结果；采样行不能证明精确/模糊匹配、唯一性或权限范围。
- 登录态更新或采集超过 24 小时不强制重新采集；同一项目、环境、入口的旧依据可复用并累积来源。真实浏览器执行仍需有效登录态，页面实际改变时需定向更新。
- 修改确认后的数据/规则会改变依据版本；相关旧脚本不能跳过版本核对。生成前核对计划与测试数据，不凭空补充业务预期。

## 5. 测试计划与模块/用例脚本

### 5.1 创建与审核计划

在测试计划中 AI 生成或手工编写，推荐每条标题 `### TC-01 用例名称`，说明前置条件、步骤、测试数据与预期。计划修改后撤销审核。模型配置为空时仍可手工管理和运行脚本。

### 5.2 建立模块，再选择生成范围

推荐：已审核计划 → 建立用例模块（也可从测试脚本 → 从计划建立模块）。核对完整用例清单和模块名称，建立后展开“项目 → 模块”，每个用例先显示“未生成”。

- **单条生成**：在目标用例旁点击“生成此用例”，窗口默认只勾选该条。选择已确认页面依据后提交。
- **整个模块生成**：点击“生成模块脚本”，默认勾选全部缺失用例，逐条独立生成。已生成用例不覆盖、不重复执行。
- **已生成用例重新生成**：模块“查看/编辑 → 单用例管理 → 重新生成”。结果先作为候选，在执行中心查看前后差异并接受；不会直接覆盖。
- 原“测试计划 → 生成脚本”仍可一次生成整份模块脚本，生成器会处理确认清单的全部条目，不抽样。

模块指一份计划/脚本集合，列表以模块名、用途、修订号与短编号区分不同记录或版本。已有脚本按现有模块名/脚本名显示，不复制或迁移其代码；无 manifest 的旧手工脚本从显式 test() 识别用例，可编辑和试运行，但补齐缺失项需要先建立完整计划清单。

每次支持 1–200 条确认用例。某条缺少定位/数据时保存已成功部分并显示缺口，其余继续处理。未生成不计通过，不用 skip、占位或永真断言替代。定位不足可自动 Explorer 恢复：默认每轮 6 步、最多 2 轮，可设 1–8 步、1–3 轮；无新依据提前停止，纯业务规则/数据缺口不重复点击页面。

### 5.3 编辑、管理与回收站

模块“查看/编辑”集中显示标注/重命名、删除模块、单用例管理及整份源码。单用例编辑只替换目标 test()，保留其名称和其他源码。支持显式 test() 和命名 test.describe()，动态注册、别名或 skip/only 需用整份编辑器处理。

单用例候选修复保守检查断言数量、匹配器、否定条件和预期参数，拒绝通过 catch/soft 降低验收标准；这不是语义正确性证明。合法调整业务预期需先更新规则并人工审核代码。单用例修改保留最近 20 次差异；修订号不是任意历史版本回滚。

计划和模块删除进入回收站，不删除关联历史任务/报告；有排队或运行关联任务时拒绝删除/恢复。恢复后重新审核，脚本重新验证。生成/补齐期间编辑、重命名或删除记录，会拒绝旧结果覆盖。仅标注管理信息不主动撤销已完成验证，但会阻止正在生成的旧版本结果写回。

### 5.4 断言与验证

全量生成可选择严格匹配、业务含义匹配、人工确认的等价文案。PRD 未限定展示载体时可接受弹窗、告警或页面提示；明确文案/业务结果/权限/状态要求优先。不用运行时大模型相似度把任意提示判通过。

默认只生成并静态检查。管理员或项目所有者可勾选逐用例浏览器验证并确认真实操作范围；每条生成后最多执行一次，失败代码保留，后续用例继续处理。分别统计代码覆盖与验证结果，生成完整不等于通过。每条验证 60 秒，进程兜底 70 秒；任务验证及附带探索累计预算 10 分钟，已启动步骤可按自身时限结束，后续标为未验证。

失败操作/断言及页面可访问性快照可触发定向探索，作为重新生成的修复依据。不自动重跑有副作用的失败操作，不自动应用修复，不直接将脚本失败认定为产品缺陷。

模块试运行和单条试运行都会真实执行业务操作。单条仍运行公共初始化/清理。修改代码撤销原审核/验证。基于页面依据的模块需覆盖完整、无未解决缺口、静态检查通过后即可审核执行；试运行不是必需步骤。本版不包含逐用例豁免审批。

## 6. 执行中心与在线报告

按项目、功能模块折叠任务；模块分组优先使用计划/模块稳定标识，名称只做展示。页面采集、无法归属的历史任务单独显示，不按相同业务名称跨项目混合。

任务类型区分计划生成、全量脚本生成、单条重新生成、缺失补齐、定向探索、单条/整组试运行、正式执行和结果分析。任务详情按用例展示覆盖、执行步骤、错误与报告，日志、建议、分析和产物列表分别展开。筛选支持项目，搜索支持任务名称、模块、用途和编号。

报告与产物：

- 在线打开 Playwright 原生 HTML 报告，不需下载解压或运行 show-report，不新增监听端口。
- 单条生成验证报告位于 verify-TC-xx/html-report。支持截图、视频、文本预览和单文件/ZIP 下载；文本超过 2 MB 提示下载，视频支持 Range。
- Trace 时间线尚未集成在线 Viewer，继续下载 Trace ZIP 查看。逐条生成验证保存截图/Trace；正式整组执行还可保存失败视频。
- 报告以无同源权限的 sandbox iframe 打开；临时链接 30 分钟有效，注销、权限撤销或 API 重启失效。拒绝路径穿越、符号链接与 storage.json 下载。
- 旧任务有原 html-report 目录即可在线查看；只有 ZIP 不自动解压。历史 results.json 不超过 10 MB 时可提取用例分组。
- generation-progress.json 和 generated-cases.spec.ts 保留已生成进度，取消/中断后可下载已保存部分。取消不会撤销目标系统操作。

## 7. 配置与开发

完整项目需要 Node.js 24+、Playwright 1.63.0、mysql2、TypeScript 和 MySQL 8.4。依赖版本由 package-lock.json 锁定；浏览器必须与 Playwright 版本匹配。旧 macOS 无法运行匹配浏览器时，优先在 Docker/Linux 环境开发和验收，不强行复用旧版 Chromium。

首次安装使用现有完整项目：复制 .env.example 为 .env，修改三个不同密码后再构建。已有安装保留 .env，不覆盖凭据。

| 配置 | 用途 |
| --- | --- |
| ADMIN_PASSWORD | 首次空库管理员初始密码，至少 6 位 |
| DB_NAME / DB_USER / DB_PASSWORD | 应用 MySQL 数据库与账号 |
| MYSQL_ROOT_PASSWORD | MySQL 初始化管理密码 |
| PORT | 宿主机访问端口，默认 8080 |
| LLM_BASE_URL / LLM_MODEL / LLM_API_KEY | Chat Completions 模型；Base URL 到 /v1，不带 /chat/completions |
| COOKIE_SECURE | HTTPS 部署设 true；本机 HTTP 开发为 false |

模型可通过兼容 Chat Completions 的 DeepSeek/网关调用；不内嵌 Codex CLI。生成/诊断会发送需求、确认的数据、定位依据、代码和必要错误上下文，不发送项目 storageState 文件。模型输出仍需审核。

```bash
bash start.sh
docker compose ps
docker compose logs --tail=100 mysql api worker
```

默认地址 http://127.0.0.1:8080。MySQL 不映射到宿主机，Compose 内通过 mysql:3306 访问。现有 image 标签即使仍为 testhub-ui:1.2-mysql 也可复用，标签不决定平台功能版本；使用新标签时需同时修改 api/worker。

源码开发可用既有 compose.dev.yaml：

```bash
docker compose -f compose.yaml -f compose.dev.yaml up -d
# 前端保存后刷新；后端保存后重启
docker compose -f compose.yaml -f compose.dev.yaml restart api worker
```

正式发布不加载开发挂载配置。接公司外部数据库时，另行调整 Compose 的 DB_HOST、mysql 依赖和服务；当前内置配置强制 DB_HOST=mysql。

## 8. 从 1.3.0 / 1.3.1 / 1.3.2 升级到 1.3.3，保留原数据卷

本交付是累计源码更新包，不是独立完整安装包或 Docker 镜像。保留原 Dockerfile、Compose、.env、软件源/证书修复与数据；此次没有新增依赖，package/lock 仅更新平台版本号。新字段存入原记录 JSON，users 表沿用 1.3.0。新建项目记录 ownerId；旧项目不改所有权，不清库。

1. 等待任务结束，关闭远程登录窗口，备份源码、部署配置、MySQL 和 data 卷。
2. 保持原项目目录、Compose 项目名和卷名；不要执行 down -v。
3. 将 ZIP 根目录内容合并覆盖到原项目根目录。README 为统一说明，旧 UPDATE 文件替换为导航页。
4. 重建 api/worker，重新登录。

备份及重建示例（现有 api/worker 共用 api 构建镜像）：

```bash
mkdir -p backups
docker compose stop api worker
docker compose exec -T mysql sh -c 'MYSQL_PWD="$MYSQL_PASSWORD" mysqldump -u"$MYSQL_USER" --single-transaction --no-tablespaces "$MYSQL_DATABASE"' > backups/pre-1.3.3.sql
docker compose run --rm --no-deps --entrypoint tar api -czf - -C /app/data . > backups/pre-1.3.3-data.tar.gz
# 确认备份成功，覆盖源码后：
docker compose build api
docker compose up -d --no-deps --force-recreate api worker
docker compose ps
docker compose logs --tail=100 api worker
```

若 api/worker 各自 build，则两者都构建。镜像 build 失败不会修改现有卷；排查原 Dockerfile 镜像源或 CA 信任问题，保留先前已验证修复。API 健康后再启动 Worker。

MySQL 初始化环境变量只对空卷生效；已有卷不能只改 .env 就重置数据库密码或创建新库。出现 1045/健康检查失败时核对数据库实际账号与配置，不要删卷“重装”。HTTP APT/证书故障不是应用数据问题，不应通过关闭证书验证长期处理。

回滚：停止 api/worker，恢复备份源码或原镜像并重建服务，不删除数据卷。旧版本缺少本版所有者权限，账号访问行为会改变；数据库/业务数据不会因代码回滚自动复原。

## 9. 更早 SQLite 数据迁移（可选）

从原 SQLite 安装升级到 MySQL 时，在新版 API 首次启动前迁移；MySQL 用户忽略本节。停止旧 API/Worker，备份完整 data（含 DB/WAL、auth、runs），保留原 Compose 项目名。

```bash
docker compose build api
docker compose up -d mysql
# 等 MySQL healthy，目标 records/jobs/workers 必须为空
docker compose run --rm --no-deps api npm run db:migrate -- /app/data/testhub.db
docker compose up -d --no-build
```

迁移保留原 ID/历史；queued/running 改为 interrupted，避免自动重复业务操作。临时任务 storageState 清除，auth 文件保留；事务失败回滚，不修改原 SQLite。MySQL 与报告文件分别备份。

## 10. 部署到离线服务器

先在可联网开发环境验收，再按服务器架构构建。例如 x86_64：

```bash
docker buildx build --platform linux/amd64 --load -t testhub-ui:1.3.3-mysql .

docker save -o testhub-1.3.3-images.tar testhub-ui:1.3.3-mysql mysql:8.4
```

传输镜像包及已修改 api/worker image 标签的 Compose，服务器使用自己的 .env：

```bash
docker load -i testhub-1.3.3-images.tar
docker compose up -d --no-build --pull never
```

不把开发机 .env、node_modules、登录态或数据卷打入镜像。迁移数据另行备份恢复。反向代理保留 Host，并放行 /report、/report.js、/report-assets/ 及 Range 请求。已有服务器继续沿用原 Compose 项目名与卷。
